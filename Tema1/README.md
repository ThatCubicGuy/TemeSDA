# Synopsis
This program implements the requested emergency services system, complete with queues of different priorities, unit management & dispatch, recalling units in case of a misjudgement and displaying relevant data in human readable formats.
## Collections
In order to manage all the data pertaining to units, incidents, and interventions, a rigorous collection framework is necessary. I've gone about doing that using concepts from other languages implemented in a generally user-friendly manner (as much as C would allow me, of course). Thereby, every collection included in this homework is generic and implements `IEnumerable`.
## Generics
Working with different data types can be annoying, since many times we require multiple methods that do the same thing for a slightly different data type. One solution is to work with void\*, and allocate everything on the heap. This is a reasonable solution, but working with void\* can also be a pain, since they need to be cast each time they are used. Some languages offer "generic" methods and types, which take one or more type parameters and create multiple versions of themselves specialized for each type used. C is not one of those languages. For this homework, I've chosen a hybrid approach using heap allocation but avoiding void* through a C implementation of "generics" using macros. Each "generic" "class" has both a \<name>T.h and a \<name>Implement.h header, one with the method signatures and type definitions (just like a regular header), and one with the entire source code, both packed into a #define with a (T) parameter. To use these generics, one must include the \<name>T.h header in any files that use it and define the type they want to use it for (e.g. `ENUMERABLE_DEFINE(int)`); then, in a separate file such as "Implements.c", implement every method for all the types used (e.g. `ENUMERABLE_IMPLEMENT(int)`). Now, we can use collections specialised for integers. Great!
## Enumerables
In C#, the System.Collections.Generic assembly contains the interfaces `IEnumerable<T>` and `IEnumerator<T>`. These are very useful for working with collections, since they unify any collection that implements these interfaces into "enumerables", which can then be used with methods specific to enumerables. Here, I have only implemented a very useful keyword - `foreach`, which is like a for loop but simplified. All it does is iterate through every item of a collection.
## Macros
I may get some flak for creating macros with snake_case naming, but there is a good reason for it. Macros such as `new()`, `foreach()`, `alloc()`, and more are intended to be used in code in a natural manner. In short, I've tried reimplementing the feel of languages like C# and thus treat these macros as custom keywords. There are macros that I wrote in SCREAMING_SNAKE_CASE, such as `ENUMERABLE_DEFINE` - this is because they are not meant to be used in code everywhere. They are only used to declare and implement generic types.
"But what about `THROW()`?" That one is... debatable. I made it uppercase since it's not related to the library, but rather exclusive to this specific homework.

# Functionality
- Each available command has its own corresponding method which is called after command parsing alongside whatever arguments it may require.
- `CmdArgs` is a DTO, only used for keeping record of arguments to be passed. Notably, the description field is an array type that has a capacity of 256 bytes. In case of longer descriptions, said array might need to be expanded. For current tests, however, it is more than enough.
- `parse_cmd(System)` reads a string from the input file and turns it into a `CmdArgs` instance, parsing every argument of the command as well.
- Every other method does what it says on the tin.
- Every allocation is checked, either through the `CHECK(ptr)` macro, or through `allocinit(TYPE, VAR)`, which also checks pointer validity before initializing the variable.
